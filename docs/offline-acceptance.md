# Native offline acceptance before packaging

This is a record of real test evidence, not a way to turn an untested build green. No complete app has passed this contract yet. The voice dependency resolver is stopped after a tool cancellation, and its unresolved closure cannot be replaced with Splash's incompatible Python dependencies.

1. Build the exact committed source with `build_complete.sh`, supplying the verified runtime payload, the complete model payload and official macOS Whisper framework. All immutable runtime native code must have been finalized before its audited manifest was created.
2. On a supported Mac, relocate that signed app into a new path with spaces. Validate it without external Bionic/LM Studio/Hugging Face state and with outbound network denied. Do not remove personal caches: use a clean isolated state directory/account or a verified sandbox. Record the actual OS and hardware, framework/runtime/model hashes, test actions and results. Never record private screen pixels or conversation content in generic build logs.
3. Exercise each check named by `scripts/offline_acceptance.py:CHECKS`: local microphone transcription → exact Splash reply → audible Kokoro; privacy opt-out across restart and honest permission denial; repeated interruption; quit with no owned children left; one companion surface. OS permission prompts require the owner's consent. Record failed or unrun checks as such.
4. Generate the exact app fingerprint with `python3 -B scripts/offline_acceptance.py /path/to/Dot.app`. This hashes every regular file and internal symlink and rejects external links. Hashes ignore the app's absolute location. Do not modify or re-sign the app afterward.
5. Create `acceptance.json` alongside the evidence logs: schema_version 1, commit from the app's build-provenance.json, app_fingerprint_sha256, and checks keyed by every required check. Each check contains passed (Boolean), evidence_path (relative to the receipt), and evidence_sha256. A true field must describe an actually passed test supported by that evidence. Receipts are traceable test attestations, not automatic proof that a user heard audio.
6. Run `DOT_OFFLINE_ACCEPTANCE=/path/to/acceptance.json bash scripts/package_complete.sh`. It verifies the app signature, audited runtime, exact fingerprint, complete provenance, all required checks and bounded evidence hashes. It copies the app to a fresh installer staging path and checks the same fingerprint again before creating Dot.dmg. Test the mounted installer copy before delivery.

Fixtures in Tests/Python are deliberately marked fixture-only and cannot bind to the product app. CI's model-free development build remains useful for Swift/UI source checks but is not eligible for this complete installer gate. Ad-hoc signing is explicitly unnotarized; this process does not bypass Gatekeeper or certify normal distribution readiness.
