# Staged Swift/Rust service boundaries

Status: R17 design deliverable, 2026-10-14. **No Rust migration is implemented or measured by this document.** R14's broader infrastructure/migration requirement, native compilation, current complete-runtime acceptance, hardware measurements and delivery remain open. Publication is paused; this is a staged document, not a change to the running app.

> **Update (2026-10-17).** The Rust migration has since landed, but not as the single in-process static
> library this design proposes: `dot-voice`, `dot-search` and `dot-fetch` are separate Rust binaries
> built from `crates/` and shipped in `Contents/MacOS`, and Swift still coordinates the app. See
> [the Rust-only runtime](../rust-runtime.md). The staged in-process domain-module plan below remains a
> proposal; where it conflicts with the shipped architecture, the shipped architecture governs.

## 1. Decision and inspected baseline

Keep the native app and existing effect owners. Introduce Rust incrementally as **one in-process static library**, starting with a model-free, bounded parser experiment. Move domain logic only after equivalent behavior and measured value; move neither framework adapters nor persistent formats simply to change language. No new daemon, IPC layer, model instance, credential store, permission system, workflow server or database server is proposed.

This follows [CONTRIBUTING](../../CONTRIBUTING.md) and the checklist's [architecture](../BUILD_CHECKLIST.md#architecture-and-performance) and [Apple-first layer policy](../BUILD_CHECKLIST.md). The inspected checkout HEAD is `b5082946acd3e4a150e8a2fe57638fba2286edd4`, **with substantial dirty/untracked work**. HEAD alone is not this design's source revision. The accompanying `evidence/source-manifest.json` binds 60 exact working-tree inputs and `source-snapshot/` preserves them. Parent continuation reports remote main separately; neither remote state nor earlier native passes validate these local bytes.

## 2. Thin native adapters and one resident model

Keep SwiftUI/AppKit, window lifecycle, native settings, Services/drop handling and App Intents in Swift (`App.swift`, `NativeDelegation.swift`, `DotIntents.swift`). Keep capture/route/permission handling in `Speech.swift`, `VoiceEnvironment.swift`, `ScreenContext.swift`, `PlacementCapture.swift`; whisper.cpp integration in `WhisperRecognizer.swift`; actual playback and callbacks in `BionicVoice.swift`. Preserve ScreenCaptureKit/Vision and the existing killable PDFKit helper, including `ResearchPDFExtractor.closeAdmissions/drain`. Future SpeechAnalyzer/Core ML/EventKit integrations belong to thin Swift adapters only if separately selected and measured; listing them is not implementation.

A thin adapter translates framework events to bounded values, preserves framework thread/lifetime/permission requirements, and reports observed results. It must not grow a second planner or encode product state transitions independently. Conversely, replacing native file safety or TLS policy with a generic Rust library is not required to make an adapter thin. Keep today's source-fetch/Search/PDF isolation boundaries until their independent acceptance is established; as of 2026-10-17 the first two are the Rust `dot-fetch` reader under `Resources/Research/source_fetch.sb` and the capability-gated loopback `dot-search` runtime ([Rust runtime](../rust-runtime.md)).

Retain exactly one app-owned resident Qwen 3.8 27B Q4 through the pinned Splash 1.3.1 baseline and target/draft/vision assets. `AppDelegate` already sends research synthesis through `model.engine`; `BundledSplash.shared` owns process reuse. Readiness/identity must still be checked for each request. Residence does not imply inference on launch or continuous background generation.

Before later concurrent service consumers are admitted, consolidate **request admission inside the existing EngineManager**, with one active inference lease and a bounded/coalescing background slot. This is a proposed strengthening, not an existing general arbiter. Foreground conversation has priority; cancel/defer background synthesis, observe client request settlement, fence late output and then admit the foreground request. Record whether the backend really releases compute: HTTP cancellation alone is not proof. Do not spin up another runtime to mask cancellation delay. Existing warmup can prepare the same model during listening, but cannot reason on an unfinished utterance. Animation, placement and progress never call Qwen per frame/tick.

## 3. Domain contract, ownership and lifecycle

Use existing typed protocols as seams before renaming files. A future cross-language operation carries bounded domain input plus an operation ID, owner generation, sequence and expected storage revision where applicable. Swift owns IDs, clocks, authorization context and cancellation; Rust never invents external authority from data. DTO field mappings and exact limits are versioned alongside the single C header. UUIDs use 16 specified bytes; durations use monotonic elapsed values, persisted dates use explicitly versioned units. Do not persist a process's monotonic clock origin.

The following is the common behavior contract, not a new framework to build first:

1. **Admit:** the current owner checks availability, target/permission constraints and capacity, installs its retained task handle, then publishes busy state. Reentrant observers cannot admit a second operation.
2. **Run:** the sole domain owner transitions state. Adapters execute only typed, admitted effects. Any suspension or callback rechecks owner generation, sequence and cancellation. Progress records actual work; only verification receipts permit success.
3. **Cancel/foreground interrupt:** revoke publication and further effects immediately; cancel owned child work. Retain the admitted handle and native capabilities until it settles. Check cancellation between bounded pure chunks and before irreversible admission. Never present cancellation as rollback of an already committed write or OS action.
4. **Settle:** distinguish completed-and-verified, handoff, failed-before-effect, stopped-before-effect, and effect-outcome-unknown. Preserve actual completed effects even if cancellation arrived late. Existing types sometimes express unknown outcome through recovery/detail fields; adding a wire enum must map those fields explicitly, not silently relabel historical records.
5. **Pause/resume/restart:** resume from validated checkpoints and new run generations. Never replay an uncertain app/file action automatically. `NativeActionRequest.id` already makes repeated IDs receipt lookups. Research retry/cooldown/retention policies remain intact. Do not treat an actor UUID as proof that another process is dead.
6. **Quit:** permanently close admissions, invalidate generation-bound input and process owners, cancel, asynchronously drain retained tasks, then release handles and terminate. Follow `AppDelegate.applicationShouldTerminate`: search cleanup, history/notebook/memory/index/research/action flushes and PDF reaping precede its termination reply. Splash/voice retain their existing shutdown ownership. No main-thread wait, detached unowned worker, process-name kill or speculative hard-deadline guarantee.

UI models stay `@MainActor`; parsing, hashing, extraction and database work must run outside it under one serial owner per state/connection. `Task {}` created from a main-actor method is not sufficient evidence that CPU work moved off-main. Use a non-main actor for bounded pure computations; isolate genuinely blocking native I/O on a bounded serial queue where necessary. Keep operation ownership across that hop; an unbounded set of detached tasks is not an executor. Coalesce replaceable UI deltas, never terminal receipts, history delivery events or cancellation. Main-actor work should be short snapshot publication and framework calls that require it. Verify with Instruments, not annotations alone.

## 4. Evidence is data; adapters retain effect authority

`ResearchSource` in `src/ProjectBrief.swift` already distinguishes original/final URL, byte hash, extraction, timestamps, truncation and transport receipt. Preserve these distinctions across FFI, storage and retrieval. A hash identifies bytes; a matching quotation establishes provenance, not truth. `httpsOnlyV1` records application transport policy, not cryptographic or semantic verification. Legacy unmarked web evidence remains inspectable but excluded from new synthesis. Search snippets are discovery data, not supporting passages.

Screen/file/web/model content cannot approve a request, expand a selected folder, change the instruction hierarchy, enable a tool, or alter credential/permission state. Cross-language output may propose only existing enumerated actions with validated arguments. Swift rechecks the actual native target and preconditions immediately before dispatch. Keep security-scoped selection and `NativeActionFolder` descriptor identity native; pass at most operation-scoped opaque references, never convert an arbitrary returned path into a capability. An in-process library shares the host's privileges; it is not a security sandbox. Retain existing helper isolation, OS/provider constraints and confirmations without adding repetitive app permission gates.

Research sources, memory passages and task snapshots remain local apart from already-admitted research requests. No cloud LLM or conversation-upload path is introduced. No microphone audio or screenshots enter durable history/memory. Log fixed stage/error identifiers and durations, not prompts, source text, credentials or full paths.

The target is the existing `Dot/Records/records.sqlite` with namespaced versioning and system FTS5. **Today it stores only the project-source index.** “One store” is an incremental destination, not evidence that current JSON records have migrated or permission to rewrite them. UserDefaults for native preferences and selected-folder recovery files are not another application database service.

First unify **access contracts**, not bytes: inject existing owners and retain their codecs, revision rules and deletion behavior. There is no second Rust writer or shadow durable database. Initial Rust domain modules consume snapshots and return proposed mutations to the existing Swift store owner. Do not replace CryptoKit receipt hashing or Foundation codecs just to cross FFI.

A later, separately reviewed namespace migration may use the same SQLite file. Before switching one record family, specify exact UUID/date/null/Unicode/unknown-field and revision mapping; preserve source bytes while verifying a bounded import under exclusive cooperating-writer admission; test interruption, corruption, capacity and old/new-client behavior. There must be one authoritative writer per family, no indefinite dual writes, and no automatic replay of effects. A converted database is not rolled back by re-enabling a stale JSON writer. Downgrade/export, deletion of both active/legacy copies, retention and backup policy must be resolved **before** that cutover. Keep that migration disabled if they are unresolved. Native-action recovery/ledger relocation especially needs its own cross-filesystem failure design; one SQLite transaction cannot atomically include a GUI action or arbitrary file mutation.

## 6. Smallest measured pilot and subsequent gates

The first experiment is **only `BoundedSSELines` framing** (`src/InteractionCore.swift:292`), used by `EngineManager.chat` and `researchSynthesis`. It is a small byte-oriented state machine with existing exact-boundary tests and no framework, network, model, store or tool dependency. Choosing it is a low-risk way to measure FFI/dispatch/copy cost, not a claim that parsing dominates inference.

| Stage | Bounded deliverable | Admission to the next stage |
| --- | --- | --- |
| 0: baseline | Freeze exact working source/build/payload identity; collect native model-free results and instrument current parser/UI path. | Current compiler/link/test failures resolved; passing baseline identified. This document can be reviewed before that gate. |
| 1: replay-only Rust pilot | One static library and a Swift test wrapper replay synthetic SSE bytes against the unchanged Swift parser. No live stream dispatch, speech, writes or feature-default change. | Zero semantic mismatches; native C/Swift/Rust ABI tests, sanitizer evidence and complete wrapper benchmarks. Stop here if complexity/cost has no demonstrated value. |

Parsing ownership may move off-main in a separately measured variant. | Exact model-free native suite, packaging/signature checks, UI/interruption traces and later real-device voice parity. | 3: domain modules, one at a time | Progress/task reducer, research state/budget/citation logic, then indexing/retrieval and tool planning/reconciliation; history/memory domain rules only after their existing codec contracts are frozen. | Replay identical typed events; one authoritative state owner; same effect/receipt ordering, stale-event rejection, cancellation, recovery and bounded resources. ### Proposed pilot C ABI, not implemented API

Rust `staticlib` is intended for linking into existing non-Rust applications; consolidate modules in one archive rather than separate Rust runtimes. Swift can import a C header through a Clang module map and link that archive. Keep the current Xcode/direct-build/SwiftPM entry points; add no CMake build-system rewrite. Exact compiler/SDK/deployment target, architecture, native link requirements and archive hashes must be pinned in a later implementation receipt. [Rust linkage](https://doc.rust-lang.org/reference/linkage.html), [Swift C wrapping](https://www.swift.org/documentation/articles/wrapping-c-cpp-library-in-swift.html).

Proposed names: `dot_core_abi_version`, `dot_sse_create`, `dot_sse_feed`, `dot_sse_destroy`. Swift owns one non-shareable wrapper and opaque parser handle per stream, serializes every call, and frees it exactly once after its operation drains. `feed` borrows a bounded byte slice only for the call and copies at most one complete validated line into caller-owned output storage, returning consumed-byte count, output length and a fixed status. No retained Swift pointer, async callback, borrowed return string, shared allocator ownership, network call, Rust task pool or Rust timer.

Input chunks are at most 16 KiB; a line output buffer is capped at the existing 262,144-byte limit. Validate pointers/lengths/capacity and integer conversions before state mutation; report insufficient capacity without consuming input. Status distinguishes no-line-yet, line, line/stream limit, invalid UTF-8, invalid argument and internal failure. Empty lines are distinguishable from no line. Keep total-stream limit 4,000,000 bytes, exact LF/CRLF behavior, UTF-8 validation at complete-line boundaries and current EOF behavior (an unterminated tail is not emitted). The Swift caller stops after the same terminal marker/error; Rust is not an SSE JSON/tool parser.

Use the C calling convention and explicit scalar/layout definitions, never Rust/Swift enum or string layouts. Panics must not unwind across the boundary: with a consistent unwind-capable Rust build, catch Rust panics internally, return a fixed error, poison that parser and destroy it after settlement. This does not catch aborts/OOM or make invalid pointers safe; there is no crash-isolation claim. Native ownership, invalid-call and panic tests are mandatory. [Rust FFI and unwinding](https://doc.rust-lang.org/nomicon/ffi.html#ffi-and-unwinding).

Cancellation is cooperative: check before/after each bounded feed and yield between batches. A running synchronous FFI call cannot be forcibly cancelled safely. Cancel discards future output, then frees the handle after the call finishes; never free from a competing cancellation callback. Revalidate turn/generation before forwarding a line/delta to MainActor. Do not change implementations midstream after output may have reached history/TTS.

## 7. Acceptance, measurement and rollback

These are **proposed engineering gates**, not measured results or new product promises.

- **Equivalence:** replay existing `InteractionCoreTests` boundary fixtures, empty/comment/done lines, every split of multibyte UTF-8/CRLF, malformed UTF-8, exact/over line and stream limits, empty output, unterminated EOF, deterministic generated chunk partitions, stale/cancel/restart sequences and allocation/error paths. Compare ordered lines, consumed bytes and first failing byte/status. Then run existing native voice-coordinator, engine, research and history tests against both implementations without changing expected behaviors to make a port pass.
- **FFI:** compile the same header with C and Swift; verify ABI version, integer widths/layout, zero/null/capacity cases, overflow checks and ownership. Run supported Address/Undefined Behavior sanitizers and concurrency/race tooling in separate appropriate configurations; inspect leaks across repeated create/cancel/destroy. Miri, if used on Rust internals, does not validate the macOS cross-language link. No claim that arbitrary invalid foreign addresses can be validated safely.
- **Performance:** compare A=current Swift placement, B=Swift parser on the proposed worker, C=Rust parser on that same worker. This separates language changes from executor/batching gains. Use identical in-memory corpora (typical, split, max-line and near-4 MB stream), fixed build flags, cold initialization separately, warmups and at least 30 interleaved A/B/C batches. Record p50/p95 with uncertainty, allocations, copied bytes, peak resident memory, binary/startup cost and cancellation-to-drain. Include actual Swift wrapper/dispatch cost, not only Rust microbenchmarks. Keep raw timing samples and exact toolchain/source/hardware/OS identity.
- **Decision threshold:** for a live parser switch, require zero correctness regressions and no p95 pipeline/UI/cancellation regression beyond measured baseline variability; predeclare the variability calculation before running. Require a repeatable improvement in the identified bottleneck, or a documented maintainability benefit with explicitly accepted measured cost. If results are inconclusive, retain Swift and report the experiment. Proposed guardrail: no new parser-attributable main-thread work interval of 16 ms or more; verify foreground responsiveness under research/index load. A guardrail is not a universal display/latency certification.
- **Whole app:** trace main-thread work and animation hitches, Stop/next-turn readiness, memory/CPU/GPU/ANE/thermal/energy under shared Splash, foreground voice and background tasks. Measure speech-end to first **audible** response including selected silence, post-silence processing separately, and cold/warm p50/p95. Scheduled player time is not acoustic onset. Real voice/model/hardware tests remain separate from replay CI. [Apple responsiveness guidance](https://developer.apple.com/documentation/xcode/improving-app-responsiveness) is relevant; its page body was not available in this research extraction, so the numeric gate above is our proposal, not a sourced Apple threshold.
- **Recovery and rollback:** initial pilot changes no stored bytes. Keep the original Swift implementation and a build-time default-off selection during evaluation; select once before admitting a stream. On mismatch/ABI error, fail the operation truthfully and choose Swift for a future fresh operation, never replay an uncertain external effect. Roll back by rebuilding the previous implementation with the same stores/payloads, preserving the installed app. A later journal/schema cutover needs its own backward-compatibility receipt; parser rollback does not prove storage rollback.
- **Release evidence:** only the exact compiled/tested archive/header/source combination may advance. Check `Package.swift`, Xcode app/test registration, `build.sh`, warning gates, existing helper/signature/resource audits and complete assembly. Source grammar checks, portable SQL tests and historical native receipts are not a current native link or installation pass.

## 8. Open decisions and completion boundary

No additional owner choice is needed to accept this bounded R17 design: fixed model/voice/UI decisions are preserved and the current working contracts remain authoritative. Future work must resolve learned-fact retention/backup/deletion/downgrade policy before changing storage, actual backend cancellation behavior before promising preemption, and any native speech candidate only through its separate benchmark gate. Do not turn those into invented defaults here.

Current execution blockers remain native baseline acceptance and the separate publication hold; neither blocks a source-grounded design. This work ran no native build, model, benchmark, migration, installation or paid service, and changed no source in the inspected checkout. Completing R17 design must not check off broader Rust migration, one-store convergence, full responsiveness, whole-product acceptance or installation.

Evidence package: `evidence/source-manifest.json` and byte snapshots; `official-web-observations.json` and focused FFI extraction; `url-manifest.json` hashes URL strings and captured tool observations, **not raw upstream HTTP bodies**; `freeze.json`/`SHA256SUMS` bind the frozen deliverable and evidence. These are provenance receipts, not security attestations. Source-relative links in this document target the eventual repository location; evidence stays with the staged review package.
